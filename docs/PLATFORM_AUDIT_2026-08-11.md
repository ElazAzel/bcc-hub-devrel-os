# BCC HUB DevRel OS — аудит платформы

Дата: 11 августа 2026 года  
Охват: интерфейс desktop/mobile, быстрый поиск, Quick Add, задачи, dashboard, data-layer, Supabase RLS, auth/session и production smoke.

## Короткий вывод

Платформа уже пригодна для рабочего cloud-сценария: приложение русифицировано, основные сущности защищены RLS по `owner_id`, данные читаются постранично, поиск использует Supabase FTS, а production health-check подтверждает cloud-режим.

Главный риск был не визуальным, а поведенческим: важность работы определялась почти только датой, дубликаты — почти только точным совпадением, а сбой XP RPC мог перейти в раздельную запись ledger и totals. Эти места исправлены.

## Реализованные алгоритмы

### 1. Приоритизация рабочего дня

Добавлен `triageScore` в `lib/triage.ts`.

Он учитывает приоритет, просрочку, близкий срок, статус «Ждём ответа»/«Заблокировано», отсутствие следующего действия, устаревшую запись и здоровье связанного проекта. Dashboard теперь сортирует блоки «Что требует внимания?» и «Какой следующий шаг?» по полезности, а не по случайному порядку загрузки.

### 2. Устойчивое обнаружение дубликатов

`findDuplicateCandidates` теперь использует нормализацию, точные сигналы email/телефона, сходство биграмм для названий и имён, а также совпадение организации. Cloud-поиск кандидатов выполняется по коротким запросам к серверу, а не загрузкой первых 100 записей.

### 3. Отмена устаревшего поиска

Command palette теперь передаёт `AbortSignal` в Supabase RPC и отменяет предыдущий запрос при новом вводе. Защита `requestId` сохранена, поэтому старый ответ не может перезаписать новый.

### 4. Безопасный полнотекстовый фильтр

Пользовательский поисковый ввод ограничен по длине и очищается от управляющих символов PostgREST `.or()`. Это уменьшает риск сломать фильтр специальными символами и ограничивает лишнюю нагрузку.

### 5. Точный dashboard count

Dashboard теперь использует `total` из серверной пагинации для KPI, поэтому количество проектов, задач, людей и событий не ограничивается первыми 80 строками.

### 6. XP только атомарно

Удалён клиентский fallback, который мог отдельно вставить contribution и отдельно пересчитать totals. В cloud-режиме теперь используется только `apply_ambassador_contribution`; если RPC недоступен, пользователь получает ошибку и данные не расходятся.

## Отложенные улучшения

- Analytics и Calendar всё ещё собирают ограниченное окно записей; для очень больших рабочих пространств стоит вынести их агрегаты в SQL views/RPC с диапазоном дат.
- Для Task Board можно добавить подсказку «проведи вправо» при первом открытии на мобильном.
- Для нескольких таблиц стоит добавить weighted search vectors, чтобы заголовок и следующий шаг имели больший вес прямо в PostgreSQL.

## Ограничения аудита

Скриншоты показывают seed/local состояние и не доказывают полную доступность для screen reader, реальную скорость на больших объёмах или поведение всех маршрутов после авторизации. RLS и production schema проверены отдельно миграциями и REST smoke, но полноценный multi-user e2e требует двух подтверждённых Supabase аккаунтов.
